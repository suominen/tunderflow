TUNderflow (CVE-2026-81000) is an integer underflow in the Linux kernel
TUN/TAP driver (drivers/net/tun.c). tun_set_headroom() stored a
requested receive headroom in tun->align with no upper bound, and
tun_get_user() uses align both as skb headroom and, via
SKB_MAX_HEAD(align), to size the linear part; an oversized headroom
propagated through Open vSwitch (netkit under VXLAN in the PoC) makes
SKB_MAX_HEAD underflow, the length wraps, and tun_alloc_skb() leaves
skb->data 64 bytes past its 4,096-byte head, so the copy from userspace
writes out of bounds. Impact: kernel oops or local privilege escalation
to root (public PoC); reachable with CAP_NET_ADMIN in an attacker-owned
network namespace, i.e. by any local user where unprivileged user
namespaces are enabled. Not remotely reachable.
The canonical fix is 447c9303942c (net: tun: bound receive headroom), first released in
v7.3-rc1. The bug was introduced by eaea34b23c46 in
v4.6, so the reachable window is 4.6 through 7.1, and 7.2 before 7.2.4.
The bug is arch-independent and old (2016): no in-support kernel
predates it, so no "Not affected" rows exist. Upstream 7.1.y went EOL at
7.1.13 without the fix and has no row. TUNderflow is one of four bugs
disclosed together (DirtyAH6 CVE-2026-80844, PPPoEject CVE-2026-68121,
DiagSpill CVE-2026-74469), each with its own tracker; never infer this
tracker's verdicts from a sibling's — a distro cherry-pick can carry
one fix without the others. Only the 447c9303942c backport flips a row.

Working-tree hygiene: stream a fetch through a pipe — `curl -fsSL <url> |
grep …` — when one pass over the data is enough. If you genuinely need a
scratch file, save it in the worktree under a `.scratch-` prefix (e.g.
`.scratch-advisories.json`), work on it there, and `rm` it before you
commit — never `git add` a scratch file. Write it with `curl -o
.scratch-…` or `… | tee .scratch-… > /dev/null`: a shell redirection into
a file (`> .scratch-…`) is refused by Claude Code even inside the
worktree, and retrying it in another spelling is wasted effort
(`/dev/null` is the one redirection target that passes). Read it back
with an allowlisted reader (`zcat .scratch-x.gz | grep …`,
`jq … .scratch-x.json`).
Don't use /tmp: Bash file reads are confined to the worktree, so a file
there can be written but not read back. The wrapper's `git clean -fd`
sweeps forgotten scratch on the next run, but the only thing you should
leave behind is the edited tracker (and its commit).
